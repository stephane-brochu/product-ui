# v0.2.0 migration

v0.1.0 snapshots and URLs remain immutable. Update the consumer script before upgrading; v0.2 manifests support selected items and explicit npm dependencies. Run the existing drift check and review local modifications first.

- Core adds PageContainer, PageHeader, SectionHeader, Checkbox, Textarea and feedback/status exports. Native IDs and aria-describedby stay intact; Checkbox supports refs and mixed state.
- Import ui-layout.css and ui-feedback.css once. Remove duplicated ds-page, ds-section-header and extracted feedback rules from a consumer's legacy stylesheet after reviewing product-specific selectors.
- Dialog/Drawer are optional. Declare @radix-ui/react-dialog exactly 1.3.1, select core,dialog and import ui-dialog.css. Wrap your product with ThemeBoundary. The document theme remains the fallback outside a boundary.
- PageHeader defaults to h1; SectionHeader to h2. Set headingLevel when composing them inside another document. SectionHeader id identifies its heading.
- StatusLabel remains a neutral emphasis compatibility helper. Use StatusBadge tone explicitly when severity matters. ErrorState no longer promises that saved records are unchanged; products should supply accurate messages.
- Dialog title and description are required. dismissible=false blocks close controls, Escape and outside dismissal while work is pending. Controlled owners may still explicitly set open=false on success. Keep persistence, failure recovery and unsaved-change policy in the product.
- ToastNotification is presentational, with caller-owned lifetime and queue. Popover, menus, tables, navigation and finance-specific views are later extraction work.

The standalone starter adopts core only. The finance adapter reexports shared components from existing entry points and updates its Bitcoin settings form without changing form names, action or value serialization.
