# v0.3.0 — Everyday controls

Milestone 1 completes the everyday-control extraction. Existing v0.1.0 and v0.2.0 snapshots remain unchanged.

## Install and styles

Core now installs 17 source/style files and requires React 19, with no Radix dependency. Add ui-composition.css to the existing core CSS imports. It contains disclosure, settings and metadata styles. The starter includes it.

Popover and action-menu are optional items. They share ui-floating.css and ThemeBoundary. Declare @radix-ui/react-popover exactly 1.3.1 and @radix-ui/react-dropdown-menu exactly 2.2.1 before using the deterministic installer. Dialog remains optional with its existing exact dependency. The installer retains previously selected items when upgrading, verifies source/dependency drift and refuses unmanaged overwrites.

```sh
npm install --save-exact @radix-ui/react-popover@1.3.1 @radix-ui/react-dropdown-menu@2.2.1
node scripts/consume.mjs install --project /path/to/product --version 0.3.0 --registry https://brochu-product-ui.vercel.app/r/v0.3.0 --items core,popover,action-menu
```

The shadcn CLI can also install individual item URLs. Its package-manager settings may save dependency ranges; retain exact pins if also using the deterministic consumer checker.

## Selection contracts

RadioGroup and SegmentedControl export from ui/selection. Both use a fieldset/legend with native radio inputs. SegmentedControl is now a single-choice radio group, rather than independent aria-pressed buttons. Update tests and consumers to use radio roles; route navigation still belongs in links.

- Supply label, unique option values and option labels. Optional per-option descriptions are linked separately from the accessible name.
- Controlled groups use value/onValueChange; uncontrolled groups use defaultValue and participate in native form reset. Do not switch between controlled and uncontrolled modes during a mounted instance.
- name determines native FormData serialization. Without a supplied name, a unique generated name isolates groups. Only the checked enabled option submits. required uses browser constraint validation; a disabled fieldset disables the group.
- A removed selected option leaves no checked option; the product chooses any replacement. Empty groups render emptyMessage. With no radio inputs there is no native required constraint; the product must validate or disable submission until choices exist. No implicit All option or value coercion is added.
- Group description/error and external aria-describedby are linked to the group and choices. Stable caller group IDs are supported; option IDs derive from the group.
- Switch accepts native checkbox attributes/ref, label, description and error. It submits its configured value only while checked. Mixed and read-only states are excluded. Finance keeps Toggle as a compatibility alias to Switch.

## Disclosure and composition contracts

Disclosure is a server-compatible native details/summary wrapper. title is the summary; children are the body; count is optional. defaultOpen sets initial expansion; native onToggle, name, IDs/classes and refs remain available. Actions and other interactive controls belong in the content, not nested inside summary.

ControlledDisclosure is an explicit client module with open/onOpenChange. Use it for validation reveal and other product-controlled expansion. Its summary click/keyboard activation requests a state change; the owner must update open. Closing while focus is inside the body returns focus to summary. Exclusive native name groups are excluded from the controlled API because browser auto-closing would bypass the owner. Reveal a failed field before moving focus into it; the component does not infer form errors.

SettingsGroup accepts title/description, headingLevel (default h3) and native section attributes/ref. Give it an id for an automatic heading relationship, or supply aria-labelledby. SettingsRow accepts label/description and a control slot, plus native div attributes/ref. Every slotted control still needs its own accessible label; the row does not guess that relationship.

MetadataList renders dt/dd entries from stable item IDs, term, value and optional action. Only null/undefined uses emptyValue (default Not provided); zero remains zero and an intentionally empty string remains empty. Empty items produces an empty definition list; compose EmptyState outside if an explanation is needed. Values, date/number formatting and missing-value language are product-owned. Long values wrap and rows stack on phones.

## Floating contracts

Popover requires title, a single ref-capable trigger and children. It supports open/defaultOpen/onOpenChange, modal (default false), and contentProps for ref, alignment, collision and focus handling. It includes no forced Done button; compose PopoverClose. Finance retains its historical Done action in a local wrapper.

DropdownActionMenu accepts stable action IDs, visible labels, callbacks and optional disabled/destructive flags. label names the trigger/menu; a custom ref-capable trigger is optional. It supports open/defaultOpen/onOpenChange, disabled, emptyLabel and contentProps. Empty menus show a disabled item. Arrow navigation, typeahead, Escape and focus return use Radix. Selection closes by default; event.preventDefault keeps it open. Callbacks are synchronous selection notifications; the product owns requests, errors, confirmation and pending policies. Destructive styling alone does not perform confirmation.

Wrap products in ThemeBoundary to preserve tokens through portals; without it they inherit document tokens. Floating surfaces use --ui-layer-floating and constrain size to viewport/available space. Avoid transformed/contained ancestors that change fixed-position geometry. These items do not provide searchable comboboxes, nested submenu APIs or application routing.

## Finance adoption

The existing adoption PR pins 23 portable files from core, dialog, popover and action-menu. Existing forms/overlays/structure entry points delegate to canonical components. Native disclosures across 13 modules adopt the shared pattern. Account cadence uses the native radio contract; chart ranges use shared segmented radios; chart event controls use Switch through Toggle. Bitcoin settings uses shared settings patterns/Switch; statement validation uses MetadataList; valuation export uses action-menu without changing CSV columns or values.

Financial calculations, permissions, source access, richer picker composition and async confirmation policy remain in finance. Removing duplicate legacy settings/floating CSS establishes one style owner. Showcase-only APIs were not treated as proof of live adoption.
