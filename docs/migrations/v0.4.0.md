# v0.4.0 — Standardized data presentation

Milestone 2 adds portable table primitives, metrics/deltas, toolbar/pagination/export UI, source references and an optional interactive DataTable. Prior v0.1.0, v0.2.0 and v0.3.0 snapshots remain immutable.

## Install and CSS

Core now installs 23 source/style files and has no Radix dependency. Add ui-data.css and ui-metrics.css to the existing core CSS imports. Interactive DataTable is an optional item, also without extra npm dependencies. The finance consumer selects core, dialog, popover, action-menu and data-table (30 files total).

```sh
npx shadcn@4.23.0 add https://brochu-product-ui.vercel.app/r/v0.4.0/core.json https://brochu-product-ui.vercel.app/r/v0.4.0/data-table.json
node scripts/consume.mjs install --project /path/to/product --version 0.4.0 --registry https://brochu-product-ui.vercel.app/r/v0.4.0 --items core,data-table
```

The deterministic installer retains existing selected items and detects source/dependency drift. Resolve any previously unmanaged file collision deliberately before adoption. Finance moved its old DataTable implementation behind a finance/data-table adapter, then adopted canonical ui/data-table source. Do not silently overwrite a product-owned implementation.

## Native tables

Table, TableHead, TableBody, TableRow, TableHeaderCell, TableCell, NumericCell, EmptyRow and TableScrollRegion are server-compatible and forward supported native attributes/React 19 refs. Table adds density, optional caption/captionHidden and stickyHeader. Supply one meaningful native caption or aria-label; do not add a second caption if composing one manually. HeaderCell defaults to column scope; supply row scope for row headers. NumericCell aligns supplied display content; it does not parse or format it. EmptyRow requires positive colSpan.

TableScrollRegion requires a meaningful label and is keyboard-focusable by default; bounded optionally limits height. Wide tables scroll inside their region. Critical information is not automatically hidden. Shared print CSS removes bounded scrolling and sticky positioning, repeats header groups and keeps rows together. Product-specific print composition stays local.

## Metrics and changes

Metric accepts label, display-ready value, optional unit/comparison/status/description slots, prominent, headingLevel (default h3), missingValue and native article attributes/ref. MetricGroup supplies responsive density/layout without calculating totals. Null/undefined values use the missing fallback; zero remains zero, and supplied text is not reformatted. Choose headingLevel to match the containing document.

DeltaValue accepts independently formatted value/percentage, explicit direction (positive/negative/neutral/unavailable), explicit tone (neutral/success/danger), description and a missing fallback. It includes non-color direction text for assistive technology. Direction does not imply business severity. A decrease is neutral unless the product supplies another tone. Currency, date/number formatting, percentage calculations, eligibility and valuation meaning remain product-owned.

## Interactive DataTable

DataTable/ManagementTable are explicit client exports. Next consumers should define function-valued columns, filters, callbacks and details inside a client boundary. Use native Table for read-only server-rendered reports instead of converting an entire page to a client table.

- caption names the table; columns and rows require unique, non-empty IDs. rowId must return a string. pageSize must be a positive integer; page must be a non-negative integer. Columns cannot be empty.
- Column supports id/header/value/render, explicit sortable/compare, align, rowHeader, sticky and opt-in mobileHidden. Keep critical fields visible. Mobile-hidden columns reappear for print.
- Default ordering compares decimal strings exactly without Number conversion, rounding or changing display text. It supports ordinary signed decimal notation and bigint. Non-decimal text uses English natural ordering; scientific notation, localized numeric strings and date objects need an explicit comparator or normalized values. Missing/null/undefined/non-finite values sort last in both directions; default cell rendering shows a missing dash. A custom render owns its own missing display. Custom comparators must return a finite ordering result; non-finite results are treated as ties.
- Search/filter/sort/page run in memory on supplied rows. No server pagination, virtualization or remote fetching is included. Use this for bounded datasets; assess responsiveness with actual row/column complexity before large deployments.
- query/onQueryChange, sort/onSortChange, page/onPageChange, selectedIds/onSelectionChange and expandedIds/onExpandedChange support controlled state. Omit the state prop for internal state; defaultSelectedIds initializes selection. Do not switch modes during an instance. Sorting/query/filter user actions request page zero.
- Row replacement ignores stale selected/expanded IDs and clamps the displayed page. It does not emit callbacks during render; controlled owners reconcile external state. Reusing a row ID deliberately preserves that row's identity/state.
- Select-all affects the visible page only and preserves selection on other pages. Selection remains scoped to existing supplied rows even when filters hide them. rowLabel optionally supplies human-friendly checkbox/detail labels.
- Expanded detail controls expose aria-expanded and reference their rendered detail row. Content remains a caller slot; route, network, persistence and permission policy stay outside.
- loading/error replace the table body experience; onRetry is caller-owned. Empty data and empty search/filter results use the documented empty state. Export is disabled for loading/error/empty results and during exporting.
- onExport receives every filtered row, in current sort order across all pages. It is not a selection-only export. The library does not serialize, download, sanitize or mutate records. exportError and exporting are caller-supplied. Finance preserves its exact raw-value/schema/formula-safe CSV serializer in its adapter.
- Printing an interactive table includes currently rendered rows/expanded details only. For a complete report, render the full dataset with native Table; product reports and statements do this.

## Supporting patterns

TableToolbar accepts a label and control/action slots. ResultCount accepts filtered count, optional total and selected count. Pagination accepts a zero-based page/pageCount, pending and either an onPageChange callback or supplied previousHref/nextHref. It renders native links for server navigation and native buttons for client actions; it owns no URLs.

ExportActions renders caller-supplied export/print callbacks, labels, pending/disabled states and an error slot. Products own async execution and recovery. SourceReference renders a supplied href/label/detail and preserves native link attributes/ref; new-tab links get an explicit cue and noopener/noreferrer. Source authorization and URL construction remain in finance.

## Finance adoption

16 read-only tables and 32 metric cards use shared primitives in reporting, snapshots, statement readers, parser operations, Bitcoin and mortgage views. Source links and statement/report export actions use shared presentation. All existing interactive table consumers use the finance adapter over canonical DataTable. Legacy generic table/metric rules move to portable CSS while page layouts and print composition remain local.

Financial calculations, exact display formatters, CSV columns/raw values and source URL generation are unchanged product responsibilities. The existing adoption PR accumulates this release; finance production is not deployed by publishing the library.
