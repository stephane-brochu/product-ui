# v0.5.0 — Application navigation and form/review workflows

Milestones 3 and 4 share one release. Earlier snapshots remain immutable. There are no new npm dependencies. Optional confirmation uses the existing exact `@radix-ui/react-dialog@1.3.1` dependency.

## Install and boundaries

```sh
node scripts/consume.mjs install --project /path/to/product --version 0.5.0 --registry https://brochu-product-ui.vercel.app/r/v0.5.0 --items core,mobile-navigation,repeatable-fields,file-selection,confirmation-dialog
```

Core contains 29 files; all optional items used by finance total 40 files. Import `ui-navigation.css` and `ui-workflows.css` after existing shared styles. Confirmation also needs `ui-dialog.css` and ThemeBoundary. Retained optional items are automatically included by the tracked installer. Review local diffs before upgrading; unmanaged copies are not overwritten.

Structural `navigation.tsx`, `form-feedback.tsx`, `upload-queue.tsx`, and `review-layout.tsx` can render on the server. MobileNavigation, RepeatableFields, FileSelection and ConfirmationDialog are separate client modules. Import directly. A Next.js routing adapter that supplies Link or event callbacks lives in a product client module; do not pass component functions through an RSC serialization boundary. Server components can supply rendered slots and data without a router adapter.

## Application navigation

| Export | Contract |
| --- | --- |
| AppShell | Supplied header/sidebar/content. `mainId` supplies a focusable main and skip link; default contentAs is main. Use `contentAs="div"` inside an existing main to avoid nested landmarks. |
| Header | Supplied brand, navigation, accountControl and mobileNavigation slots. No product text, routes or authentication. |
| PrimaryNavigation / NavigationLinks | Supplied items, exact activeHref, disabled links as noninteractive spans, native anchors by default; optional linkComponent receives native href/ARIA/events/ref. Product owns route matching and authorization. |
| Sidebar | Required label, supplied items and link adapter. Responsive navigation wraps on narrow screens; no local route discovery. |
| MobileNavigation | Native button disclosure, normal Tab links, Escape restores trigger focus. Link activation, outside pointer, focus leaving, or changed navigationKey closes it. Product supplies a navigationKey that changes for programmatic routes; activeHref is the fallback. This is nonmodal navigation, not an ARIA menu; it does not trap focus or lock page scrolling. |
| Breadcrumbs | Supplied ordered labels/URLs; final crumb gets current-page semantics, including linked final crumbs. Intermediate non-links are not current. |
| SectionNavigation | Native links, supplied activeHref, optional leading slot/className. Hash destinations use current-location semantics. Product supplies IDs, scroll offsets, route resolution and any IntersectionObserver. No hidden scroll spy. |

Library links follow native browser behavior; modified clicks/open-in-new-tab remain browser-owned. Current route keys are product-owned, not inferred from URL substrings. Desktop navigation switches to the mobile disclosure at 640px. Sidebar stacks at 800px. Header/sidebar/navigation are omitted from print; content remains.

The catalogue switches Harbour workspace to Atlas support using different brand/labels/links with identical shared components. Finance's wrapper supplies Finances, financialNavigation, Next Link/usePathname and the existing Clerk account control. AdminLayout uses AppShell with a div inside the existing main; report section navigation preserves its product-owned intersection observer.

## Forms, confirmation and repeatable fields

FormFeedback is presentation only: `pending` takes priority over stale errors/success; error uses alert, pending/success use status. The optional retry callback is invoked only by user activation. It does not submit, reset, navigate, catch server errors or move field focus. The product supplies safe messages, field validation/associations and focus policy. For server-rendered use, omit onRetry. Pending UI is not a concurrency guard; product actions must retain their existing guards.

ConfirmationDialog calls onConfirm once while its promise is pending. Initial focus is Cancel; pending disables Cancel/Confirm and blocks escape/outside dismissal. A rejected callback keeps the dialog open with a supplied safe error message; the same confirmation can retry. Resolved callbacks close; closing restores trigger focus through Dialog. Reopening clears the previous error. The caller must reject on failure; resolving an error-shaped value counts as success. No deletion/auth/network policy is included. Confirmation is an optional normal modal with explicit safe-action focus, not an automatic destructive-action service.

RepeatableFields takes controlled `{id,label,content}` items and onAdd/onRemove callbacks. Caller IDs must be nonempty/unique and stable; caller data and React keys survive neighboring removal. Adding focuses the first enabled field in the new row; removal focuses a neighboring remove action, or Add when the list is empty/limited. Disabled/minItems/maxItems govern UI buttons, not server validation. Limits must be nonnegative integers; max must be at least min. The product must enforce limits in state/server code and owns serialization, reset and input validation. No index-based identity or hidden automatic JSON serialization. Native fieldset disabled behavior is retained.

## Files and upload queues

FileSelection returns original File objects through onFiles, checks configured MIME/extension/wildcard rules, positive maxBytes, empty files, batch duplicates and optional validateFile. Null MIME PDFs can match the PDF rule by extension. With multiple=false, a multi-file drop reports the constraint and returns only the first valid file. Valid files can be returned alongside rejection messages. Keyboard selection and drag/drop use the same validation; disabled controls ignore both. It clears the native input after selection so the same file can be selected again on retry. Therefore this is a selection-callback component: it deliberately excludes name/required/value/defaultValue and is not a native multipart form serializer. Products retain the files/queue and validate any required-file condition themselves.

Client accept/type/size checks are advisory. Do not trust them for content validation, authorization, confirmed duplicate detection or upload quota. No file content is read, transformed, uploaded or hashed by this component. Batch duplicate identity uses name/size/lastModified, which is only a possible duplicate signal; server hashing remains authoritative. Input attributes/ref/description relationships are forwarded. Error lists are alerts and connected to the native input.

UploadQueue takes supplied IDs/name/status/message/progress/action slots. Progress is a bounded percentage; status/message changes are politely announced separately from rapid progress updates. It has no transport, concurrency, retry/remove policy or persistence. Product adapters must retain request keys, receipt identity, authorization, retry rules and source/provenance behavior. The finance FileUpload adapter retains existing defaults and document status labels; LibraryUpload's private Blob pipeline is unchanged. PendingUploads supplies the original Finish upload callback to queue actions, with its original busy guard.

## Review and history

ReviewLayout renders supplied evidence and review in labelled sections; two columns stack below 800px in source-first DOM order. It never loads documents or authorizes source URLs. A product may retain viewer-specific sizing; shared layout owns columns, spacing and shrinking. No sticky inner scrolling or virtualized PDF reader is included.

HistoryTimeline renders caller-ordered events with supplied dateLabel/dateTime/title/detail/source. It never reorders, reformats dates, sanitizes product messages, fetches audit records or infers actor/status/provenance. Empty text is configurable; long IDs/labels wrap; print retains supplied history. The caller authorizes and constructs every source link. Finance review decisions retain their ISO timestamps, exact reason and newest-first order; its AuditHistory adapter retains the finance date formatter and actor/detail.

## Finance adoption and verification

The adoption changes presentation/adapters only. Existing create/edit actions retain FormData schemas, concurrency guards, success-only reset/refresh, safe failure messages, and retry behavior. Account identifiers remain exact strings serialized by finance. Document mutations keep endpoints, optimistic versions, authorization, dispatch/recovery and provenance. Upload bytes, hashing and receipts remain in finance. Review confirmation/acceptance flags and source reads retain existing server-side checks. No data/schema change or finance production deployment is part of this release.

Interaction coverage includes server rendering/current-link semantics, mobile keyboard/dismissal/route reset, confirmation pending/rejection/retry/focus, repeatable IDs/limits/focus/value retention, file validation/drop/reselection, callback-only queue actions and supplied history order/source URLs. Consumer and browser verification accompany release/adoption notes. Existing finance action/review/provenance regressions must pass before applying adoption.
