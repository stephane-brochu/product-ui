# v0.6.0 — Optional chart and PDF renderers

Milestone 5 separates advanced rendering from finance before a second product is introduced. Core remains 29 files and has no chart/PDF dependency. All finance-selected items total 47 files; there are 48 registry items. Prior snapshots remain immutable.

## Independent installation

Charts have no new npm dependency:

```sh
npx shadcn@4.23.0 add https://brochu-product-ui.vercel.app/r/v0.6.0/time-series-plot.json
npx shadcn@4.23.0 add https://brochu-product-ui.vercel.app/r/v0.6.0/comparison-plots.json
```

`core,time-series-plot,comparison-plots` installs 33 files and no PDF code. Import `ui-charts.css` plus the documented dependencies' shared styles. `chart-primitives` can be installed separately. All chart modules are explicit client modules; import directly without a global barrel.

The generic viewer accepts any compatible loader and needs no PDF.js dependency:

```sh
npx shadcn@4.23.0 add https://brochu-product-ui.vercel.app/r/v0.6.0/pdf-viewer.json
```

The separate optional PDF.js adapter requires an exact pin, checked before consumer files are written:

```sh
npm install --save-exact pdfjs-dist@6.4.299
npx shadcn@4.23.0 add https://brochu-product-ui.vercel.app/r/v0.6.0/pdfjs-loader.json
```

`pdfjs-loader` installs eight source/style files including its transitive native controls; it does not require any chart. Import `ui-pdf.css` with theme/control/composition styles. The deterministic consumer supports the same optional items and retains previously installed items:

```sh
node scripts/consume.mjs install --project /path/to/product --version 0.6.0 --registry https://brochu-product-ui.vercel.app/r/v0.6.0 --items core,time-series-plot,comparison-plots,pdfjs-loader
```

Resolve intentional local modifications before upgrading. No published snapshot is overwritten. The installer does not install npm packages, execute scripts, copy workers, choose URLs or grant source access.

## Chart contracts

| Export | Responsibility |
| --- | --- |
| ChartFrame, ChartHeader, ChartToolbar, ChartFooter | Named frame, supplied title/description/action/content, native frame props/ref and optional heading level. Product controls filter/export/footer composition. |
| ChartCanvas | Named SVG viewBox and supplied graphical children. No financial interpretation or image export. |
| ChartLegend | Controlled series visibility, native toggle buttons, optional compact mobile disclosure. Removed hidden IDs are ignored when protecting the last visible series. Caller retains its visible-series state and enforces any additional policy. |
| ChartEventList | Caller-ordered supplied date labels/timestamps and event content; no date formatting, sorting or inferred events. |
| TimeSeriesPlot | Line, grouped bar and signed stacked-bar plotting, responsive width, pointer/touch exploration, keyboard summary, tooltip and native exact-value table. Loading/error/retry/empty states are presentation only. |
| PlotTooltip | Supplied point/series plus explicit value/date formatters. It displays source values; no recalculation. |
| groupPlotValue | Display-only grouping of the integer portion of exact decimal strings; retains sign, fractional digits and trailing zeros. Null/undefined/blank and nonfinite numbers display missing. No currency/rounding policy. |
| ComparisonBars | Supplied row IDs/labels/display values and fractions clamped to 0–1 for geometry. Caller supplies ordering, grouping, totals, changes and percentages. |
| WaterfallPlot | Supplied start/end coordinates, formatted values, labels and total markers. Calculates no total, contribution or reconciliation. Repeated labels are supported. Text equivalent follows the plot. |
| RelationshipFlow | Supplied from/to/value/detail nodes. No account identification, transfer inference or authorization. |
| Sparkline | Supplied finite numeric geometry, null/nonfinite gaps and visible isolated samples, with an accessible textual sequence. No automatic trend, return or severity inference. |

TimeSeriesPlot accepts `points: {id?, date, values, status?, annotation?, dashed?}[]`, `series: {id,label,pattern?,dashed?}[]`, `kind`, title/unit, height, optional display/date/axis formatters, annotation/table switches, loading/error/onRetry. Dates are ISO calendar dates; invalid dates are excluded and valid dates are stably sorted without mutating input. Duplicate dates can share a position; supplied IDs must be unique/nonempty (otherwise date/index identities are generated). Series IDs must be unique/nonempty. Use one unit/basis per plot; product adapters select compatible series.

Values are unformatted decimal strings or finite numbers. Null/undefined/blank/nonfinite values have no coordinate and are never converted to zero. Missing samples break line segments. The `dashed` flag/pattern is a visual instruction: the renderer does not assign meaning to a status string such as estimated. Grouped/signed stacked bars distinguish series with patterns as well as color; pointer hit-testing follows their rendered rectangles. Touch selects the nearest date without blocking vertical page scroll.

Keyboard exploration uses Left/Right/Up/Down, Home and End. The focusable plot exposes a slider index and exact supplied values through aria-valuetext; a visible keyboard summary follows the plot. Hover tooltips appear at plotted samples/bars; pointer exit clears hover. The default data disclosure is a full supplied-data native table with a named scroll region. `showDataTable=false` is appropriate when the product provides its own accessible table or equivalent; finance retains its existing exact data table and controls. `tableHint` describes an external table when applicable. Formatting callbacks must return strings and preserve the product's intended precision; no `Number` conversion is applied before calling them.

Coordinates are approximate JavaScript numbers. Normalized geometry avoids invalid coordinates from extreme signed finite values; stacked axis ticks outside finite numeric range say so explicitly. This is never an exact arithmetic API. Two exact strings that differ below floating-point resolution can share the same plotted position; tooltips, keyboard text and tables retain their distinct source strings. Products own any financial arithmetic, unit conversions, totals and authoritative export. Numeric examples use comma thousands separators.

Time series are bounded to 2,000 supplied points and 32 series, with height 160–2,000. Oversized inputs produce a clear limit state before plotting; they are never silently truncated. Finance keeps its full product-owned table/export available. This is not server aggregation or virtualization. Waterfalls accept at most 24 steps with finite coordinates and a finite total coordinate span. Sparklines accept at most 2,000 values. Comparison/relationship lists are ordinary DOM lists; assess supplied data volume in the product. Long labels wrap or remain available in text alternatives; SVG axis labels can be clipped within the plot to prevent page overflow. Print retains plots and exact text; interactive controls/tooltips are omitted. Charts do not download images/CSV, select reporting dates, fetch data or persist views.

## PDF loader and asset setup

PdfViewer receives a stable `loadDocument: () => {promise, destroy}`. The promise resolves to `{numPages,getPage}`, whose page handles expose `size`, cancellable `render(canvas,scale)`, `text` and optional `cleanup`. Loading/render cancellation and document teardown are exercised independently of PDF.js. `destroy` should release the whole source/document task; the viewer calls it once on disposal or rejected page-count validation. Render tasks must settle after cancellation. Supply a stable loader (useMemo/useCallback) and change `sourceKey` whenever its source or loading policy changes; the keyed session clears old state before displaying a new source. No private source URL is inferred.

The optional `createPdfJsLoader({url,workerSrc,withCredentials?,httpHeaders?,assets?})` adapter wraps pinned PDF.js. Credentials default false; finance explicitly supplies true for its existing authorized same-origin endpoint. Source URLs, headers, cookies, CORS/CSP and source-byte limits belong to the product. `assets` can supply trailing-slash cMapUrl, standardFontDataUrl, wasmUrl and iccUrl when required by the supported documents. No arbitrary request options or product environment variables are read by the shared module.

The product must serve the matching worker from its exact installed `pdfjs-dist` version. For Vite, import `pdfjs-dist/build/pdf.worker.min.mjs?url` in a product loader boundary and pass its emitted URL. For a Next.js public path, copy the installed `node_modules/pdfjs-dist/build/pdf.worker.min.mjs` to a public worker file during build (finance retains its existing prepare-pdf-worker script). Never point at an unversioned remote worker or mix library/worker versions. Configure optional fonts/CMaps/WASM/ICC assets when your documents require them; deployment copying/bundling and CSP remain explicit product setup, not automatic registry side effects.

Vite TypeScript projects also need `/// <reference types="vite/client" />` in `src/vite-env.d.ts` (or equivalent tsconfig types) to type `?url` worker/PDF imports. The current starter includes this declaration. This is product build setup; the portable registry files and hashes remain unchanged.

PDF.js is statically imported only by its optional adapter; a product can dynamically import that adapter at its own client boundary. The catalogue lazily loads the real PDF example and worker only when opened. The viewer and core never import PDF.js. Finance similarly retains lazy loading. Client-only modules should be loaded after hydration; they are not a server PDF parser or an ingestion pipeline.

## PDF viewer behavior and limits

PdfViewer requires title, sourceKey and loader. It supports controlled page/onPageChange or defaultPage, onDocumentReady, supplied pageId, safe load/render messages and a fallback slot. Controlled pages are clamped to the loaded document without emitting render-time callbacks. Page buttons are native, disabled at boundaries/during rendering, and page changes are announced. The product supplies any URL/hash synchronization and source provenance links.

Default limits: 100 pages, 1,000 CSS pixels wide, 2,500,000 pixels per raster. Configurable width is 1–4,096; maxPixels is 1,024–16,000,000; page counts/default/controlled pages must be positive integers. Invalid dimensions and exceeded page budgets reject clearly while the original-source fallback remains available. These are page/raster controls, not an uploaded-byte cap or a comprehensive font/image decoding memory limit. Preserve server-side file validation, byte limits and request authorization. A bounded offscreen render buffer prevents concurrent use of the visible canvas; the buffer is explicitly released after each render, and canceled/stale work cannot replace the new page.

The selectable-text disclosure stays open across page changes. Its old text is replaced with a pending message until the current page is ready. Text extraction failure leaves the rendered image usable with a text-unavailable explanation; render/load failure displays a safe error and preserves the supplied fallback. Scanned/image-only pages explain the absence of selectable text. Observers/listeners/render tasks are canceled/disconnected when no longer needed, with a window-resize fallback if ResizeObserver is unavailable.

PreviewFrame supplies only a labelled title/action/content/fallback frame. It authorizes nothing. The viewer renders one page, not a whole-document print/export. It is a visual review aid with a plain-text alternative, not a fully tagged/structured PDF accessibility reader. Forms, annotations, document search, OCR, signatures, password prompts, rich reading order, editing, mobile pinch zoom and whole-document printing are outside this supported scope. Open/download the authorized original for full-reader features. Paper remains white to preserve the document's appearance under either UI theme.

## Finance adoption

Finance's TimeSeriesChart retains calendar ranges, account/measure filters, visible-series state, annotations, exact finance formatters, CSV schema/raw decimal strings, valuation status and external data table. Shared TimeSeriesPlot handles geometry/interaction only. Allocation grouping, exact sums, previous-value changes and ordering remain in finance; comparison rows receive already formatted values/fractions. Waterfall/relationship/sparkline adapters retain their supplied financial labels and values. Generic styles have one canonical owner.

SourcePdfPreview retains its private source URL, explicit credentials, matching public worker path, 100-page/1,000-width/2,500,000-raster settings, safe fallback messages and source-page hash behavior. DocumentPreview uses the shared frame while retaining its original iframe sandbox and authorized original link. No upload, receipt, parser, review decision, source storage, data schema or authorization path changes.

This release prepares reuse; a second actual product is still the next validation of the library's generality. It does not claim universal framework, locale, RTL, high-volume chart or full PDF-reader support. Older selection/data/navigation/workflow contracts remain in the v0.3/v0.4/v0.5 migration guides.
