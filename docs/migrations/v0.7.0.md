# v0.7.0 — Create an option inside a selection control

`CreatableSelect` is an optional client component. Its popup contains native radio choices and a create action. Choosing create displays a text field and explicit create/cancel actions within that popup. It is a dialog popup, not a searchable ARIA listbox or remote autocomplete.

## Install and styles

Install `creatable-select` separately from core. It depends on the existing optional Popover and exact `@radix-ui/react-popover@1.3.1`, native fields/selection and their transitive styles. Import `ui-creatable.css`, `ui-floating.css`, `ui-composition.css` and the usual theme/controls/patterns/feedback styles once. Core remains 29 files. No new npm dependency was added.

## API and ownership

- Controlled `value`, `options` (`value`, string `label`, optional `disabled`) and `onValueChange`. Values must be unique non-empty strings. Option grouping is not rendered. This is intended for small lists, without search or virtualization.
- `onCreate(trimmedLabel)` returns a promise of an option. Creation uses the product's permissions, persistence, uniqueness rules and error policy. Throw a safe user-facing error to retain input for retry. Returning an existing option is valid for an idempotent create policy.
- `createLabel`, `createInputLabel`, `placeholder`, `label`, `description`, `error`, `maxLength` (default100), `required`, `disabled`, optional `name`, and `onPendingChange`.
- Created options are retained locally until unmount, so the selection survives a delayed product refresh. Supplied options take precedence for matching IDs. Products should refresh their option list after persistence and explicitly reset controlled values when resetting their form.
- The component does not own a form, server action, router, authentication, model, request URL, database or notification queue. Creating an option is a separate mutation: cancelling the parent form does not undo a successfully created option.

## Validation and interaction

A visually hidden native select owns FormData and required validation even while the popup is closed. It is excluded from the accessibility tree and sequential focus; the visible labelled combobox button owns interaction. Invalid submission focuses that trigger and exposes its error. Missing, removed or disabled selected values serialize as empty. A disabled field is omitted from FormData. Exact string IDs are never converted to numbers.

Radio choices use native arrow-key behavior. Enter in the creation field invokes create without submitting the surrounding product form. Draft input survives failure or cancellation of the inline editor. Escape/outside interaction closes an idle popup and returns focus. Pending creation blocks repeat requests, Cancel, Escape and outside dismissal; connect `onPendingChange` to the parent dialog's `dismissible` and form's disabled state. Results are ignored after unmount, but requests are not aborted and server-side persistence may already have completed. An unmounted caller must not assume a pending callback completion.

`TextInput` now explicitly accepts React19 native input refs. Its rendering and all previous attributes/value semantics remain unchanged. v0.6.0 and earlier immutable registry snapshots are retained.
